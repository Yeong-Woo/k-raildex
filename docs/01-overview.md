# 01. 개요 — 목적·범위·승계 제약

## 1. 서비스 정의

**한국철도도감(K-Raildex)** 은 대한민국 철도의 **현재 정보**(노선·역·운행 계통·열차 등급·열차번호·차량번호·계획 시간표)와 **계획 정보**(상위 계획·계획 사업·사업 단계·근거 고시·환승센터)를 **출처와 함께** 읽기 쉽게 제공하는 비상업 공개 웹사이트다. 공개 주소 `https://k-raildex.com`.

차별점: 미래철도DB 수준의 정보 깊이 + 읽기 쉬운 구조·화면 + 모든 사실에 출처·확인일.

## 2. 재구축 목적

기존 시스템은 다음 구조로 동작한다(future-rail-db/docs/design/platform-architecture.md 4-2절).

```
공공데이터 원본(raw 251MB) + 수기 YAML(data/own, 34파일·27 kind, 그중 다수가 "보정(override)" 파일)
  → 빌드 스크립트(build.ts 1,660줄: 역 병합·이름 정규화·순서·좌표·파생 필드 계산)
  → data/build/*.json → DB 개체 테이블(jsonb) → API → Next.js SSR
```

D 단계에서 원천을 DB(`own_record` = YAML 조각 보관)로 옮겼지만 **데이터의 실체는 여전히 "YAML + 빌드"** 다. 그래서

1. 레코드 하나를 고쳐도 전체 빌드·검증(수십 초)이 돌아야 반영된다.
2. 사람이 고치는 대상이 "개체"가 아니라 "보정 파일 항목"이라(예: 역 좌표는 `station_coord`, 노선 이름은 `line_override` 의 `kric:I4101:경부선` 키) 관리 앱이 개체 단위 편집을 직접 제공할 수 없다.
3. 개체 테이블은 `data jsonb` 문서형이라 관계 무결성(FK)을 DB 가 보장하지 못하고 검증 스크립트에 의존한다.

새 시스템의 목표:

| #   | 목표                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------- |
| G1  | **DB 가 유일한 원천**. 개체는 정규화된 관계형 테이블의 행이고, 화면·API 는 DB 를 직접 읽는다. YAML·빌드 단계가 없다.                |
| G2  | **스키마 정돈**: 기존 16개 JSON Schema + 27개 원천 kind + 보정 파일을 하나의 일관된 관계형 모델로 재정의한다(03 문서).              |
| G3  | **관리 앱 우선**: 모든 개체를 조회·생성·수정·삭제할 수 있는 관리 앱을 먼저 만든다. 모든 쓰기는 검증·감사 기록을 거친다.             |
| G4  | **세련된 공개 사이트**: React 기반으로 다시 설계한 화면(기존 기능 승계 + 디자인 개편).                                              |
| G5  | **Closed Loop(후순위)**: 노선·역·계획 정보를 찾아 제안(변경 묶음 초안)을 만드는 수집기·LLM 에이전트 → 사람 승인 → 반영의 순환 구조. |
| G6  | **미래 지도**: 계획·공사 중 노선이 완공됐을 때의 노선도를 연도별로 지도에 표시한다(2026-11-20 추가, 06 문서 3절).                   |

## 3. 범위

### 3-1. 포함

- 개체: 출처, 운영기관(공개 페이지 없음), 역(환승 그룹), 노선별 역, 노선, 열차 등급, 운행 계통(정차 패턴), 상위 계획, 계획 사업(범위 노선·역·시설, 반영 내역·단계 이력·기대 일정·노선·역 역할·관련 계획·선형), 연표 이벤트, 열차번호대, 차량번호대(편성), 환승센터, 공개 노선도, 계획 시간표, 용어(→ R-Q34), 원문 문서.
- 앱: 관리 앱, API, 공개 사이트, worker(작업 큐: 수집·파생 갱신·백업), 이관 도구.
- 첨부: 모든 개체에 근거 원문 발췌·링크·이미지·문서. 공개 가능한 원문은 공개 사이트에서 다운로드.
- 지도: MapLibre + VWorld 배경, OSM 선형(ODbL, 분리 보관), 자체 역 좌표, 계획 노선 선형, **연도별 미래 지도**. 관리 앱 전용 구글 지도 위성 비교.

### 3-2. 제외(기존 결정 승계)

- 부동산(실거래가·역세권), 실시간 열차 위치, 이용자 계정·커뮤니티·댓글, 광고·유료 기능·후원 결제.
- 외부 사이트(미래철도DB 등) 데이터 복제.

## 5. 기존 시스템 대비 바뀌는 것

| 영역        | 기존                                                                                                              | 새 시스템                                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 원천        | `own_record`(YAML 조각) + raw 파일 → 빌드                                                                         | 정규화 관계형 테이블(개체·관계)                                                                                              |
| 수기 보정   | 보정 파일 20여 개(override 키로 자동 생성 결과에 덧씀)                                                            | **없음.** 이관 때 보정을 개체에 실체화(materialize)하고, 이후에는 개체를 직접 고친다. 외부 코드 대응은 `external_ref` 테이블 |
| 파생 필드   | 빌드가 계산해 JSON 에 기록(`areas`, `line_classes`, `service_kinds`, `line_ids`, 상속 `review_status`, 자동 연표) | DB 뷰·물리화 뷰로 계산(저장 안 함) (Q26·Q27 A)                                                                               |
| 쓰기        | 변경 묶음 YAML → 승인 → worker 가 전체 재빌드(수십 초)                                                            | 개체 단위 트랜잭션(수십 ms) + 변경 묶음(changeset)으로 감사 기록. 변경 묶음 형식은 대량·에이전트 제안용으로 유지             |
| 검증        | `validate.ts`(AJV + 참조 검사, 빌드 뒤)                                                                           | DB 제약(FK·CHECK·UNIQUE) + 도메인 검증 규칙(쓰기 전, 03 문서 8절)                                                            |
| 백업        | data/ YAML·JSON 내보내기 + git                                                                                    | `pg_dump` 정기 백업 + 공개 데이터 덤프(JSON/CSV) (Q40 A)                                                                     |
| 원문 파일   | git 안 `data/public/raw`(251MB)                                                                                   | 문서 저장소(오브젝트 스토리지) + `document` 메타 테이블 (Q39 A)                                                              |
| 관리 앱     | 변경 묶음 대기열 + YAML 편집기 + 일부 보정 편집기                                                                 | 모든 개체의 폼 기반 CRUD + 특수 편집기(역 순서·정차 패턴·지도·단계 타임라인) + 이력·되돌리기                                 |
| 공개 사이트 | Next.js SSR, 컬렉션 전체를 메모리에 캐시                                                                          | Next.js SSR(Q6 A), 페이지별 API 조회 + 데이터 판 기반 캐시                                                                   |

## 7. 핵심 용어 (요약)

정의 원문은 DB 용어 사전(`glossary_term`, 이관 전에는 future-rail-db/docs/TERMINOLOGY.md).

| 용어            | 뜻                                                                                                                                                    | 모델                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 노선(물리 노선) | 선로 시설. 법적 분류 + 광역철도 지정 여부                                                                                                             | `line`                    |
| 노선별 역       | 노선마다의 역(순서·영업거리·역번호·이름·상태·개통일). 역은 이를 묶는 그룹                                                                             | `line_station`            |
| 운행 계통       | 열차가 실제 다니는 단위(수도권 전철 1호선, KTX 경부선)                                                                                                | `service`                 |
| 정차 패턴       | 운행 계통 안 완행·급행 등 정차역 목록                                                                                                                 | `stop_pattern`            |
| 열차 등급       | KTX·ITX-새마을·무궁화호 등 종별                                                                                                                       | `train_class`             |
| 열차번호대      | 열차 1회 운행에 붙는 번호의 범위 체계                                                                                                                 | `train_number_range`      |
| 차량번호대      | 차량 1량의 번호(호대)·편성번호(호기) 체계                                                                                                             | `rolling_stock_range`     |
| 상위 계획       | 국토종합계획·국가철도망 구축계획·도시철도망 구축계획 등                                                                                               | `plan_program`            |
| 계획 사업       | 상위 계획의 한 행(노선·사업구간)                                                                                                                      | `plan`                    |
