# 참고 사이트 분석 (벤치마크)

- 조사일: 2026-10-11
- 대상: 미래철도DB, noseon.do(미래 지하철 노선도), 미래철도20XX
- 출처: 각 사이트 메인 페이지·용어 페이지·건설절차 페이지, HTML 소스의 meta/script 태그, 노선 상세 페이지 1건(noseon.do 수도권 1호선)
- 사용 원칙: 구조·분류 방식·UI는 참고하되 **데이터는 복제하지 않는다** (CLAUDE.md 정확성 원칙)

## 참고 사이트 분석: 미래철도DB

사용자 평가: **정보의 질은 상당히 높다. 그러나 UI/UX, 특히 가독성이 매우 나쁘다.**
→ 이 프로젝트는 정보 깊이는 미래철도DB 수준을 목표로 하되, 분류·탐색·화면은 새로 설계한다.

### 사이트 구조

- 성격: "신설예정 철도·지하철·광역전철·경전철 노선 정보 사이트". 개인 운영(한우진), 1990년대 후반부터 운영.
- 메뉴 구성
  - 신설예정 철도정보: 지역별(1.htm) / 개통시기별(2.htm) / 신설예정역(005.htm) / 폐기된 계획(004.htm)
  - 안내: 최근 업데이트(날짜별 변경 로그, 과거분 whatsnew1.htm) / 미래철도DB란?
  - 정보: 철도 건설절차·사업상황 신호등(con1.htm) / 용어(word.htm) / 링크 / 언론소개
  - 커뮤니티: 네이버 카페(노선도), 유튜브, 방명록 등 외부 링크
- 분류 축: **지역별**과 **개통시기별** 두 축이 기본. 역 단위(신설예정역), 상태(폐기)는 별도 목록.
- 사업 단계 표현: "사업상황 신호등" 4단계(구상 → 계획 → 설계 → 시공). 색상 정의는 원문에 없음.
- 갱신 방식: 메인 페이지에 날짜별 텍스트 업데이트 로그. 노선 페이지 단위로 수기 갱신으로 추정.

### 배울 점 (정보 설계)

- 노선마다 "현재 어느 단계인가"를 한 눈에 보여주는 상태 표시
- 폐기된 계획을 버리지 않고 별도 보관 → 역사 추적 가능
- 개통시기별 정렬 → "언제 무엇이 열리나"라는 이용자 질문에 직접 답함
- 변경 로그 공개 → 신뢰성. 다만 노선 단위 변경 이력은 없음
- 건설 절차와 용어를 별도 페이지로 설명해 초보 이용자 진입 장벽을 낮춤

### 개선할 점 (UI/UX)

- 1990년대식 정적 HTML, 프레임·표 레이아웃. 모바일 대응 없음
- 노선 목록이 긴 텍스트 표로만 제공되어 훑어보기 어려움
- 검색·필터(지역 × 단계 × 개통 연도 조합) 없음
- 지도 기반 탐색 없음(노선도는 외부 카페에 의존)
- 노선별 변경 이력, 출처 링크가 본문에 섞여 있어 구조화되지 않음
- 변경 로그가 메인 페이지 하나에 누적되어 특정 노선 변경 추적이 어려움

### 이 프로젝트에서의 활용 원칙

- 구조·분류 체계·용어 설명 방식은 참고한다.
- **데이터(노선 목록, 설명문)는 복제하지 않는다.** 1차 출처(고시, 보도자료, 공공데이터)에서 직접 수집한다.
- 용어 중 통용 정의(평면환승, 선상역 등)는 출처를 밝히고 docs/TERMINOLOGY.md에 반영했다.

## 참고 사이트 분석: noseon.do — 미래 지하철 노선도

### 개요

- 소개 문구: "GTX와 전국 도시철도의 과거·현재·미래 노선, 역과 개통 일정을 지도에서 탐색"
- 실제 데이터 범위: 지역 구분이 **수도권만** 존재. 노선 36개(1~9호선, GTX-A/B/C, 신분당선, 신안산선, 위례선, 동북선 등), 역 808개.
- 운영 주체·데이터 출처·면책 표기: 페이지 본문에서 확인되지 않음.

### 정보 구조

- 3개 축: **일정(events)** / **노선(lines)** / **역(stations)**. URL도 `/events/수도권/…`, `/lines/수도권/1호선`, `/stations/수도권/역명` 형태로 동일하게 설계.
- 일정은 1974년부터 "2036+년"까지 연도별로 묶인 타임라인. 각 항목은 유형이 있다: 구간 개통, 역 개통, 역명 변경, 환승 개시, 운행 중단/종료.
- 날짜 표현: 완료된 사업은 실제 날짜(예: 2025년 6월 28일), 예정은 "예정"(월·상반기 단위 허용), 미정은 "일정 미정".
- 미확정 역명은 "G01정거장 (향동천역)", "P175정거장 (풍기역)"처럼 **정거장 코드 + 가칭** 병기.
- 노선 상세 페이지: "수도권 1호선 노선도·개통 정보"처럼 노선도와 개통 이력을 한 페이지에.

### 화면·기술

- 지도 기반 SPA. 네이버 지도 API(oapi.map.naver.com) 위에 deck.gl 레이어로 노선을 그리는 것으로 보임(폰트명 "Pretendard DeckGL", 프리커넥트 도메인에서 추정).
- React 계열 SSR 프레임워크(entry.client / root / map-layout 청크 구조, React Router v7 또는 Remix 계열로 추정). 서버 렌더링으로 역·노선·일정 링크가 HTML에 모두 포함되어 검색 엔진 노출에 유리.
- 하단 드로어(subway-data-drawer), 타임라인 상세 시트(timeline-detail-sheet) 등 모바일 우선 UI.

### 배울 점

- **일정 / 노선 / 역을 동일한 1급 개체**로 두고 서로 링크 → 이 프로젝트의 데이터 모델 후보.
- 개통뿐 아니라 역명 변경·환승 개시·운행 종료까지 "이벤트"로 기록 → 변경 이력을 자연스럽게 축적.
- 미확정 역명 표기 규칙(정거장 코드 + 가칭)이 명확.
- 과거(1974년~)까지 포함해 "현재 노선도가 어떻게 만들어졌는가"를 보여줌.

### 한계 (이 프로젝트가 채울 부분)

- 수도권만. 전국 일반철도·고속철도·지방 도시철도 없음.
- 사업 단계(구상/예타/설계/시공)가 아니라 "개통 예정일" 중심. 예타 통과 여부 같은 **계획 진행 상태는 보이지 않음**.
- 출처·근거 문서 링크 없음. 운영 주체 불명.
- 용어 설명, 계획 체계(국가철도망 구축계획 등) 설명 없음.

## 참고 사이트 분석: 미래철도20XX (metro20xx.kr)

### 개요

- 자기 소개: "미래 교통과 실거래를 함께 보는 **부동산 의사결정 도구**". 발행 주체는 "포비전"(JSON-LD publisher).
- 핵심은 부동산이며 미래철도는 그 입력 데이터. 메뉴(페이지 제목 기준): 미래철도 노선도 / 미래철도 노선 목록 / 부동산 인사이트 / 맞춤 아파트 선택 분석 / 부동산 사주 / 부동산 안목 테스트 / 부동산 결정 복기.
- 사용자 방침: **부동산 기능은 이 프로젝트의 관심사가 아님.** 철도 노선도·노선 목록 부분만 참고한다.

### 철도 부분

- 노선 목록 페이지 설명: "노선별 역 목록, 개통 목표와 **공식 출처**를 확인" → 노선마다 출처 링크를 두는 것으로 보임. "노선 수혜역", "착공 준비" 같은 상태 문구 존재.
- 노선도는 **카카오 지도** 기반 + 별도 **도식 노선도(schematic map)** 데이터를 함께 불러옴(코드 내 FUTURE_RAIL_CATALOG_URL, SCHEMATIC_MAP_URL). 즉 지도형과 도식형을 모두 제공하는 구조.
- 실거래 데이터는 "국토교통부 실거래가 신고자료 기준"으로 표기.

### 화면·기술

- 프레임워크 없는 순수 JS 모듈 SPA(해시 라우팅 `#/home`), PWA(manifest, 앱 버전 1.2.283). 클라이언트에서 JSON 카탈로그를 받아 렌더링하므로 HTML에 콘텐츠가 없어 검색 엔진 노출은 약함.
- 데이터 파일은 비공개 경로(직접 접근 불가).

### 배울 점

- 노선 단위 **공식 출처 링크**를 UI에 노출하는 점(이 프로젝트의 "현실에 입각" 원칙과 일치).
- 지도형 + 도식형 노선도를 같은 데이터에서 함께 제공하는 구조.

### 한계

- 부동산 중심이라 철도 정보의 깊이(사업 단계, 계획 체계, 용어)는 얕음.
- 수도권 중심(확인 필요).
