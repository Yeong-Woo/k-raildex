# 라운드 운영 방식

이 프로젝트는 "구현 → 결정 질문 → 답변 → 구현"을 여러 라운드 반복한다. **round-N.md 는 코드 리뷰 문서가 아니라, 그 라운드의 구현을 끝낸 뒤 사용자(운영자)의 판단이 필요해진 질문을 모은 파일**이다.

- docs/REFERENCE.md: 구현 **전**에 필요한 질문(Q1~Q17)과 그 결정 사항.
- docs/review/round-1.md: 1차 구현 **후** 생긴 결정 질문(Q18~). 답변을 받으면 그대로 구현한다.
- docs/review/round-2.md: round-1 답변을 반영해 구현한 뒤 새로 생긴 질문. 이후 같은 방식.
- docs/review/notes.md: 구현 중 "이건 나중에 물어봐야 한다"고 느낀 지점을 적어 두는 임시 메모. 라운드 파일을 쓸 때 재료로 쓰고 비운다.

## 규칙
- 한 번에 한 라운드. round-N.md 는 round-(N-1).md 의 답변이 모두 반영된 뒤에 만든다.
- 질문 번호는 REFERENCE.md 부터 이어서 매긴다(중복 금지). 답변은 사용자가 `답변:` 칸에 적는다.
- 질문 형식은 REFERENCE.md 와 같다:
  ```
  ### Q{n}. 질문 한 줄
  - 배경: 왜 결정이 필요한지 (구현 중 알게 된 사실 포함)
  - 선택지: A / B / C
  - 임시 가정: 답이 없는 동안 따르는 가정 (= 추천)
  - 답변:
  ```
- 결정이 아닌 것(단순 검수, 정리, 버그)은 질문으로 올리지 않고 "답변 없이 진행하는 작업" 절에 적고 그냥 한다.
- 답변을 받으면: 구현 → 결과 요약을 round-(N+1).md 머리말에 한 줄로 적고 → 새 질문을 이어 쓴다. 지난 라운드 파일은 수정하지 않는다(기록).
