# 리뷰 운영 규칙

설계 문서(docs/01~10)의 모호한 점을 질문으로 모아 답을 받고, 답을 문서에 반영하는 방식으로 설계를 확정한다. 기존 시스템의 "round-N" 방식을 승계한다.

## 파일

- `round-01.md`: 1차 설계 문서에 대한 질문(이 파일부터 시작).
- `round-02.md` …: 답변 반영 후 새로 생긴 질문. 한 번에 한 라운드.
- 지난 라운드 파일은 답변 칸 외에는 수정하지 않는다(기록).

## 질문 형식

```
### Q{n}. 질문 한 줄
- 배경: 왜 결정이 필요한지(기존 시스템에서 확인한 사실 포함)
- 선택지: A / B / C
- 추천: 선택지 + 이유 한 줄. 설계 문서 본문은 이 추천을 채택했다고 가정하고 썼다.
- 영향: 바뀌는 문서·절
- 답변:
```

## 답변 방법

- `답변:` 칸에 선택지 기호만 적어도 된다(예: `A`). 추천을 그대로 받으면 `추천` 또는 `OK`.
- 선택지 밖의 생각은 자유롭게 적는다.
- 빈칸으로 둔 질문은 **추천안을 임시 결정으로 보고 진행**한다(나중에 바꿀 수 있지만 비용이 커지는 질문은 표시 ★).
- 번호는 라운드를 넘어 이어서 매긴다(round-02 는 Q67 부터).

## 반영

1. 답변을 받으면 해당 설계 문서를 고치고, 각 문서의 `(→ R-Qn)` 표시를 결정 내용으로 바꾼다.
2. `docs/decisions.md`(첫 반영 때 생성)에 결정 표(질문·결정·날짜)를 누적한다.
