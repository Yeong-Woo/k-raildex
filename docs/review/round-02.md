### Q70. ★ "노선마다 따로 두는 역"의 단위와 형태는?

- 배경: GTFS 는 승강장(stop)을 역(parent station) 아래에 둔다. 우리 모델에서 노선별 역은 사실상 지금의 노선-역(`line_station`) 행과 1:1 이다. 문제는 그 단위를 **독립 개체(자기 id·URL)** 로 만들지, 노선-역 행을 확장할지다.
- 선택지:
  - A. **2단계 모델, 노선-역 확장**: `station` = 환승 그룹(공개 역 페이지 단위, 기존 id 유지) / `line_station` = 노선별 역(자체 이름·운영기관·상태·개통일·역번호·외부 코드·좌표를 가짐, 공개 URL 없음 — 역 페이지 안의 노선별 절)
  - B. **2단계 모델, 독립 개체**: 노선별 역마다 새 id(`stn-sadang--seoul-2` 등)와 상세 페이지를 두고, 그룹(`station`)이 묶는다. 이관 때 새 id 약 1,700개 생성
  - C. 운영기관 단위로 분리(같은 운영기관의 여러 노선은 하나로, 예: 서울교통공사 2·4호선 사당)
- 추천: **A** — Q25 B 의 의도(노선마다 역 정보를 따로 둠)를 만족하면서 URL·id 를 새로 만들지 않는다. 노선마다 다른 이름·개통일·역번호를 모두 담을 수 있다.
- 영향: 03 4-5·4-7절, 05, 06, 07
- 답변: A

### Q71. 어떤 정보를 그룹(역)에 두고, 어떤 정보를 노선별 역에 둘까?

- 배경: 지금은 이름·좌표·상태·개통일이 역 하나에만 있다. 환승역이면 노선별로 개통일이 다르고(예: 4호선 개통 후 수인분당선 추가), 표기가 다르거나(TAGO·운영기관별 이름), 운영기관이 다르다.
- 선택지:
  - A. 그룹: 대표 이름(ko/en/한자)·대표 좌표·시·도·주소·역 종류·철도역 정보 원문(역연혁·역소개·역등급)·병합 대상. 노선별 역: 이름(그룹과 다를 때만)·운영기관·상태·개통/폐지일·역번호·외부 코드(TAGO id 등)·좌표(승강장 위치를 알 때만)·순서·km. 그룹의 상태·개통일은 노선별 역에서 계산(가장 이른 개통, 하나라도 운영 중이면 운영 중)
  - B. A 와 같되 그룹의 상태·개통일도 따로 저장
  - C. 직접 지정
- 추천: **A** — 같은 사실을 두 곳에 저장하지 않는다(Q26 A 원칙).
- 영향: 03 4-5·4-7·6절
- 답변: A, 환승역이 아니더라도 station 객체가 존재해야해.

### Q72. 다른 개체는 그룹과 노선별 역 중 어느 쪽을 가리킬까? 그리고 그룹으로 묶는 기준은?

- 배경: 정차 패턴·시간표는 특정 노선의 승강장 단위 정보이고, 계획·환승센터·이벤트는 역 단위 정보다. 그룹 기준이 필요하다. 예를 들어 이름이 다른데 통로로 이어진 환승(기존 데이터는 이미 하나로 합침)이나, 이름이 같은데 떨어진 역(신촌(2호선)·신촌(경의선)은 별개 역)이 있다.
- 선택지:
  - A. 노선별 역을 가리킴: 정차 패턴 역, 시간표 세트. 그룹을 가리킴: 계획, 환승센터, 이벤트, 지도 표시. 그룹 기준 = **공식 환승역**(운영기관 안내·노선도에서 환승 표시). 이름이 달라도 하나의 그룹이고, 노선별 역 이름으로 표기 차이를 보존
  - B. 전부 그룹을 가리킴(노선별 역은 속성 묶음일 뿐)
  - C. 직접 지정

- 답변: A

### Q89. ★ 미래 노선의 선형은 무엇으로 그릴까? 직선 선형은 허용할까?

- 배경: 출처별 선형 품질 — ① 공사 중 노선은 OSM 공사 선형(ODbL, 2026-10 기준 일부 노선만 매핑) ② 공식 위치도에서 추출한 traced 선형(기존 2026-10-18 기준 18건) ③ 경유역 직선(schematic). 미래 지도는 이 선형이 주인공이라 품질이 곧 화면 품질이다.
- 선택지:
  - A. 우선순위 OSM 공사 선형 > traced > schematic. schematic 은 **경유역을 부드러운 곡선으로 잇고 "개략" 표시**(가는 점선 + 범례 "선형 미확정"). 관리 앱 품질 대시보드에 "미래 지도 대상인데 traced 선형 없음" 목록을 두고 traced 를 계속 늘린다
  - B. traced·OSM 선형이 있는 계획만 그린다(schematic 은 제외, 역 점만 표시)
  - C. schematic 도 직선 그대로 표시
- 추천: **A** — 빠짐없이 보이면서 정밀도를 숨기지 않는다. 다만 곡선 보간이 실제 선형처럼 보일 위험이 있어 "개략" 표시가 필수다.
- 영향: 03 4-11절 plan_geometry, 05 FR-ADM-073, 08(traced 추출을 에이전트 과제 후보로)
- 답변: A

### Q90. ★ 계획과 기존 노선의 관계(연장·개량·대체 후 폐선)를 모델에 넣을까?

- 배경: 완공 후 모습을 그리려면 "새 선이 생긴다"는 사실만으로는 부족하다. ① 연장 사업(서울 9호선 4단계 등)은 기존 노선 색으로 이어서 그려야 하고 ② 개량·복선화 사업은 선이 늘지 않으며 ③ 선형 이설·대체(중앙선 구선 등)는 새 선이 개통되면 **옛 구간이 사라진다**. 지금 `plan_line` 은 단순 연결이라 이 구분이 없고, 미래 폐선 예정일도 담을 곳이 없다.
- 선택지:
  - A. `plan_line` 에 역할 추가: `new`(신설 노선이 됨) / `extends`(기존 노선 연장 — 그 노선 색·이름으로 표시) / `upgrades`(개량, 지도 변화 없음) / `replaces`(개통 시 대체되는 구간·노선 — 미래 시점에서 숨김, 해당 노선-역 범위 지정 가능). 계획 역(`plan_station`)에도 `new` / `existing`(환승 생김) / `closes`(폐역 예정) 역할
  - B. 신설·연장만 구분(new / extends), 대체·폐선은 다루지 않음
  - C. 계획마다 "완공 후 노선 구성"을 별도 스냅샷 데이터로 직접 입력
- 추천: **A** — 데이터는 조금 늘지만 연도별 화면을 규칙으로 계산할 수 있고 개통 처리 마법사(05 FR-ADM-059)와도 맞물린다.
- 영향: 03 4-11절(plan_line·plan_station 역할), 05 FR-ADM-053~055, 06
- 답변: A

### Q91. 미래 노선의 색과 이름은 어떻게 정할까?

- 배경: 공식 노선색(C-1: 출처 필요)이 정해진 계획은 드물다(GTX-B·C 정도). 미확정 색을 임의로 정하면 공식 색처럼 오해된다.
- 선택지:
  - A. 연장(extends) → 기존 노선 색. 공식 색이 있으면(출처 기록) 그 색. 나머지는 **단계 대표색**(시공·설계·계획 단계별 중립 색 계열) + 지도 위 계획 이름 라벨
  - B. 계획마다 운영자가 임의 색을 지정(화면에 "임의 색" 표시)
  - C. 모두 단계 대표색
- 추천: **A**
- 영향: 03(plan 에 color + 출처 field), 06
- 답변: A

### Q92. 개통 목표가 없거나(미정) 지난 계획은 연도 슬라이더에서 어떻게 다룰까?

- 배경: 개통 목표(target_open)는 퍼지 날짜이고 미정이 많다. 목표가 지났는데 미개통인 사업도 있다(지연).
- 선택지:
  - A. 연도 = 개통 목표의 시작 연도(`target_open_from`). 미정은 슬라이더 끝의 "목표 미정" 칸에서만 표시. 목표가 지난 미개통 사업은 현재 연도에 "지연" 배지로 표시. 정보 패널에 목표 출처·단계를 함께 표시
  - B. 미정은 표시하지 않음
  - C. 연도 슬라이더 없이(Q87 C) 이 문제를 피함
- 추천: **A**
- 영향: 03 6절(`v_unopened_target` 재사용), 06
- 답변: A

### Q93. 지리 지도 외에 "도식 노선도"(지하철 노선도처럼 직선·45도로 정리한 그림)도 만들까?

- 배경: "노선도"라는 표현은 지리 지도가 아니라 도식 노선도를 뜻할 수도 있다. 도식 노선도는 자동 생성이 어렵고(배치 알고리즘 또는 수작업 좌표 필요) 별도 데이터(역별 도식 좌표)가 든다.
- 선택지: A. 지리 지도만(이번 요구 범위) / B. 수도권 등 일부 권역에 도식 노선도도 만듦(도식 좌표를 관리 앱에서 편집) / C. 나중에 검토
- 추천: **A** (도식 노선도는 C 로 후보 기록)
- 영향: 06
- 답변: A
