## 1. 원칙

| ID         | 요구사항                                                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-API-001 | API 는 DB 의 **유일한 쓰기 관문**이다. 관리 앱·수집기·에이전트·이관 도구 모두 같은 도메인 적용기(`packages/domain/changeset`)를 거친다.                                    |
| FR-API-002 | 요청·응답 형태는 `packages/contracts` 의 zod 스키마가 정의하고 OpenAPI 3.1 을 자동 생성한다(Q10·Q11 A).                                                                    |
| FR-API-003 | 경로 영역: `/v1/public/*`(공개 사이트 SSR 서버 전용 읽기), `/v1/admin/*`(관리 앱·관리자 CLI), `/v1/agent/*`(제안 전용).                                                    |

| FR-API-007 | 소프트 삭제된 개체는 기본 응답에서 제외. 관리 API 는 `include_deleted=true` 로 볼 수 있다. 공개 API 는 볼 수 없다(삭제 id 요청 시 410 Gone, 리다이렉트가 있으면 301 정보). |

## 4. 관리 API — 개체 CRUD

대상: `source, operator, station, line-station, line, train-class, service, plan-program, plan, event, train-number-range, rolling-stock-range, transfer-center, route-map, glossary-term, document, attachment`.

| 메서드·경로                              | 내용                                                                                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/admin/{type}`                   | 목록. 공통 쿼리 `q`, `status`, `review_status`, `region`, `area`, `updated_since`, `include_deleted`, `sort`, `limit`, `offset` + 개체별 필터 |
| `GET /v1/admin/{type}/:id`               | 상세(관계 포함) + `version` + `derived`(계산값: 역 상태·계획 현재 단계·개통 목표·권역 등) + `referenced_by` 요약                              |
| `POST /v1/admin/{type}`                  | 생성(즉시 반영). 201 + 변경 묶음 id + Soft 경고                                                                                               |
| `PATCH /v1/admin/{type}/:id`             | 부분 수정. `If-Match: <version>` 필수. 관계 목록은 전체 교체                                                                                  |
| `DELETE /v1/admin/{type}/:id`            | 소프트 삭제(사유). 활성 참조가 있으면 409 + 참조 목록                                                                                         |
| `POST /v1/admin/{type}/:id/restore`      | 휴지통 복구(하위 행 함께)                                                                                                                     |
| `DELETE /v1/admin/{type}/:id?purge=true` | 영구 삭제(휴지통에 있는 것만)                                                                                                                 |
| `GET /v1/admin/{type}/:id/history`       | 변경 이력                                                                                                                                     |
| `POST /v1/admin/{type}/:id/revert`       | 이 개체의 op 하나 되돌리기. 본문 `{ changeset_id, seq }` → 역 op 를 새 변경 묶음(origin revert)으로 적용. `dry_run=true` 면 미리 보기         |
| `POST /v1/admin/{type}/validate`         | 저장 없이 검증만                                                                                                                              |
| `GET /v1/admin/trash?type=`              | 휴지통                                                                                                                                        |

공통 쓰기 옵션: `rationale`, `changeset_title`, `dry_run=true`.

### 4-2. 변경 묶음·여러 건 입력

| 경로                                                | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/admin/changesets?status=&origin=` · `/:id` | 목록·상세(op 전/후·근거·오류)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `POST /v1/admin/changesets/:id/preview`             | 현재 DB 에 적용했을 때 diff·검증(롤백)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `POST /v1/admin/changesets/:id/approve`             | 본문 `{ comment?, op_seqs?, force? }`. 전체 또는 `op_seqs` 일부 적용 — 나머지 op 는 새 draft(`meta.split_from`, 응답 `remainder_changeset_id`, 근거도 함께 이동). 제출 때 기록한 `base_data_version` 이후 대상 개체가 바뀌었으면 409(`details[].rule = base_data_version`, draft 유지), `force: true` 면 건너뜀                                                                                                                                                                                                                                                                                     |
| `POST /v1/admin/changesets/:id/reject`              | 반려(사유)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `POST /v1/admin/changesets/:id/revert`              | 되돌림 묶음 생성·적용(origin revert, `reverts_changeset_id`). create→삭제, update→그 op 가 바꾼 필드만 이전 값(그 뒤 같은 필드가 바뀌었으면 409), delete↔restore, rename_id→옛 id 로, 첨부 변경→그 첨부를 이전 상태로. merge_station·purge 는 409. 두 번 되돌리기 409. `dry_run=true` 지원(첨부 제외)                                                                                                                                                                                                                                                                                               |
| `GET /v1/admin/bulk/targets`                        | 대상(`station`·`line_station`·`train_number_range`·`rolling_stock_range`·`event` + 모드 `plan_refs`·`plan_milestones`)과 입력 가능 필드 `{ name, label, kind, required }`                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `POST /v1/admin/bulk/parse`                         | 본문 `{ entity_type 또는 mode, text, mapping?, defaults?: { source_id, checked_at } }`. 붙여 넣은 표(TSV, 엑셀)·CSV(구분자 자동, 따옴표 처리), 첫 줄 = 머리글 → 열 대응 추정(필드 이름·라벨·별칭) → 값 해석(퍼지 날짜 `2028`·`2028-03`·`2028-H2`·`2028-03-01`·`?`/`미정`, 참조 id 또는 이름(역은 별칭 포함, 여럿이면 후보와 함께 오류), 예/아니요, 코드값 또는 한국어 라벨, 시·도 이름) + 계약 검증. 응답 `{ target, delimiter, fields, columns: [{ index, header, field }], rows: [{ index, cells, data, errors: [{ field, message }] }], summary }`. 노선별 역 id 는 비우면 `ls-<노선>--<역>[-n]` |
| `POST /v1/admin/bulk/submit`                        | 본문 = parse 와 같음 + `rows?`(칸 배열, text 대신) · `exclude?`(뺄 행 번호) · `title?` · `rationale?`. 포함 행에 오류가 있으면 422(`details[].path = rows.<행>.<필드>`). 아니면 draft 변경 묶음 1개(origin bulk_import, `meta.bulk`) → 201 `{ changeset_id, op_count, row_count, status: 'draft' }`. 개체 대상은 행마다 create op, 계획 모드는 계획마다 update op 하나(기존 목록 뒤에 붙임, expected_version). 반영은 변경 묶음 승인                                                                                                                                                                |

기존 시스템의 변경 묶음 YAML 형식은 받지 않는다(이관 도구만 읽음, Q82).

- 카탈로그 `params` 항목: `{ name, label, description, required, default, example, kind: text|int|date|enum|station_ref, ref_system, options, fixed }`. `fixed` 는 항상 default 로 보낸다(응답 형식 등). 기본 URL 의 `{이름}` 자리는 경로에 들어간다(서울 열린데이터처럼 키가 경로에 있으면 `key_param` 을 그 이름으로).
- `paging`: `{ page_param, size_param, total_path }` 또는 `{ start_param, end_param, total_path }`(total_path 가 없으면 `totalCount`·`list_total_count`·`total` 을 찾는다). DB 비교 설정 `compare: { code_field, name_field, lat_field, lng_field }` 는 API 에서는 별도 필드지만 DB 에는 `paging` jsonb 안 `compare` 키로 둔다(마이그레이션 없이, 03 문서 4-19-1절).
- XML 응답은 fast-xml-parser 로 JSON 변환(값은 문자열 그대로 — `00`·앞자리 0 보존). 도메인은 파서를 주입받는다.

## 7. 쓰기 처리 순서 (도메인 적용기)

```
1. 인증(Access JWT 또는 토큰 범위)
2. 계약 검증(zod)
3. BEGIN (READ COMMITTED + SELECT … FOR UPDATE)
4. 대상 잠금·version 비교(If-Match)
5. before 스냅샷 → op 적용(행·관계·entity 레지스트리) → after 스냅샷
6. Hard 검증(영향 개체 범위) — 실패 시 ROLLBACK, 422
7. changeset(applied)·change_op·data_version 기록
8. COMMIT → NOTIFY data_changed → worker(apps/worker): 2초 디바운스 → pg-boss 작업 refresh-derived(`SELECT refresh_derived()`, 큐 정책 stately = 실행 1 + 대기 1). 용어 변경이면 TERMINOLOGY.md 재생성 job(미구현)
9. 응답: 새 상태 + version + Soft 경고
```

draft 승인 때도 같은 3~9 를 묶음 단위 한 트랜잭션으로. 단건 쓰기 p95 < 150ms.
